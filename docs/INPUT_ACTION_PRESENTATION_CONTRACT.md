# Steamデモ 入力アクション／表示モデル契約

## 1. 目的

Steamデモの入力と画面表示を、CLIや将来のGUI実装から独立させるための最小契約を定義する。

PR #71でデモ進行自体は成立したが、現行CLIでは物理入力、メニュー表示、ゲーム処理呼び出しが同じ実行層に集まっている。本変更では本格GUIを導入せず、次の画面実装が依存できる境界のみを追加する。

## 2. 責務分離

### `game/app/presentation/input_actions.py`

- キーボード／ゲームパッドという入力デバイス種別を表現する
- 物理入力トークンをメニュー操作の意味アクションへ変換する
- 表示用の入力ヒントを提供する
- 同一デバイス内の重複トークンを起動時に検知する

物理キー名やゲームパッドボタン名は、このプレゼンテーション層より下へ渡さない。

### `game/app/presentation/menu_view_model.py`

- メニュー項目と選択位置を不変データで表現する
- 上下移動、決定、戻る、ガイド要求の遷移を解決する
- Steamデモの進行状態を画面描画用ViewModelへ変換する
- 推奨操作をメニュー項目へ付与する

ゲーム状態の更新は行わず、描画に必要な情報だけを生成する。

### `game/app/cli/run_steam_demo.py`

- CLI入出力を担当する
- 既存の数値選択と各 `_run_*_flow` を維持する
- メニュー内容と推奨表示は `SteamDemoMenuPresenter` から取得する

## 3. 意味アクション

| Action | 用途 |
|---|---|
| `move_up` | 前の選択項目へ移動 |
| `move_down` | 次の選択項目へ移動 |
| `confirm` | 現在項目を決定 |
| `cancel` | 現在画面を戻る／閉じる |
| `show_guide` | 現在のデモ目標を表示 |

ゲーム内の `quest_board`、`move`、`hunt`、`save` などはメニュー項目のアクションIDであり、物理入力を表す意味アクションとは分離する。

## 4. デフォルトバインディング

### キーボード

- 上: `Arrow Up` / `W`
- 下: `Arrow Down` / `S`
- 決定: `Enter` / `Space`
- 戻る: `Esc` / `Backspace`
- ガイド: `G`

### ゲームパッド

- 上: `D-pad Up` / `Left Stick Up`
- 下: `D-pad Down` / `Left Stick Down`
- 決定: `A`相当（`button_south`）
- 戻る: `B`相当（`button_east`）
- ガイド: `Y`相当（`button_north`）

これらは入力アダプターが渡す正規化済みトークンの契約であり、OS固有イベントや実機ドライバとの接続は今回の対象外とする。

## 5. メニュー遷移仕様

- 選択可能項目が0件の場合、`selected_index` は `None`
- 1件の場合、上下移動しても同じ項目を維持
- 複数件の場合、先頭と末尾は循環する
- 無効項目は上下移動時にスキップする
- 無効項目または空メニューで決定しても、ゲームアクションは返さない
- 戻るとガイド要求はゲーム状態を変更せず、操作結果として返す

## 6. SteamデモViewModel

`SteamDemoMenuViewModel` は次を提供する。

- 画面タイトル
- デモ進捗
- 現在目標のタイトルと説明
- 推奨アクションID
- デモ完了状態
- メニュー項目
- 現在選択位置
- キーボード／ゲームパッドの入力ヒント

デモ進行判定は既存 `DemoFlowService` を利用し、ViewModel側でクエストやセーブ状態を重複管理しない。

## 8. テスト観点

- キーボード／ゲームパッド入力の解決
- 大文字小文字・前後空白の正規化
- 未知入力と空入力
- 同一デバイス内の重複トークン
- 空／1件／複数件メニュー
- 先頭／末尾循環
- 無効項目スキップ
- 決定／戻る／ガイド要求
- New Game直後の推奨操作
- 工房確認ステップの専用項目
- デモ完了後の表示

## 9. スコープ外

- OSイベントの直接取得
- ゲームパッド実機接続
- Steam Input API
- キーコンフィグ保存
- GUIフレームワーク導入
- 既存CLI補助関数の全面移設

## 10. 次の拡張

1. DOMまたはゲームクライアント向けの入力アダプターを実装する
2. `InputBindingProfile` を設定画面から差し替え可能にする
3. メニュー階層とフォーカス復元を追加する
4. マウス／タッチ入力を意味アクションへ変換する
5. アクセシビリティ設定と入力ヒント表示を連携する
